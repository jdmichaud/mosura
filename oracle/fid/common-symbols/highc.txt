# Common symbols for the MetaWare High C 386 columns — callees whose presence identifies
# nothing, so they must not contribute to a function's specific hash.
#
# DERIVED, NOT GUESSED. Counted over the 341 modules of v3.31's HC386.LIB by walking the OMF
# LIBRARY structure (modules are page-aligned after MODEND; a plain record walk desyncs on the
# padding and sees only a handful of modules) and tallying EXTDEF references per module:
#
#   _mwgoc         217/341   64%
#   _mwargstack    217/341   64%
#   _mwint21        58/341   17%
#   _mw_errnoset    36/341   11%
#
# The threshold was "referenced by >= 10% of modules". The four below are High C's universal
# runtime helpers — the argument-stack helper, the general operation call, the DOS int 21h
# thunk, and the errno setter — which is exactly the shape of thing this list exists for: a
# match credited to "it calls _mwargstack" would be credited to every function in the runtime.
#
# Not included: `SMALL?`, which the same tally surfaced at 32%. It is not a symbol — it is a
# memory-model name leaking out of the record stream — so it is excluded rather than silently
# carried as if it were a callee.
#
# ⚠️ MEASURED EFFECT: NONE, for these libraries. Building highc-3.31-x86-32 with and without this
# list produces BYTE-IDENTICAL databases (300 records either way). The list is kept because it is
# a correct, derived statement of which callees carry no information, and it is wired the way
# docs/fid-building-databases.md recommends — but it is not currently buying anything, and saying
# otherwise would be a claim the evidence does not support.
#
# Why it is inert here: in a library module these helpers are EXTDEF references, so they arrive as
# unresolved by-name children, and `resolveNamedRelations` already declines to build a relation for
# them. The list would start to matter for input where those calls RESOLVE to hashed functions in
# the same program — a linked image ingested with a map, for instance.
_mwgoc
_mwargstack
_mwint21
_mw_errnoset
