## 0. How to use this plan

### 0.1 Standing rules (do not relitigate)

- **the implementer implements directly** (the owner, 2026-09-05: the worker model is retired). No second party: the
  review substitutes are the gates and commit messages that carry the numbers.
- **Small self-contained commits** (the owner, 2026-09-05): one commit per coherent step within a work package,
  each building; gate numbers on the series' last commit; suite once per package; never leave a big change
  uncommitted while gates run.
- **Where the work happens:** the main checkout `<repo>`, one branch per package
  (`git checkout -b p<N>-<name> master`), fast-forwarded into master when green. Return with
  `git checkout master`, never a SHA. **the owner pushes.**
- **Reported numbers are trusted, never re-derived**; testing your OWN change is required.
- **A defect fix ships a pinning test**; **a behaviour-neutral change passes the identity gate**
  (`docs/measurement-rules.md` §10): emit the corpus, `diff -rq` the `recovered/` trees, compare the
  `# arms:` line. **Identity baseline = `<emit trees>/tb`** (the tree of master 769f2cc; verdicts
  `<emit trees>/tb-rec.tsv`: 1031 EXACT, WGSS 0.6443 structural over the 2804 game rows). An intended
  tree change goes through the full round (`scripts/corpus-round.sh <new> tb "<label>" skipsmoke`) and is
  landed on the verdict comparison (no EXACT lost, no new failure verdict), per `docs/corpus-round-runbook.md`.
- **Suite through a file, rc echoed** (never through a pipe). `gt-arms` alone with `-- --ignored` at
  plan closure and for any commit that changes an arm, the emit plan or the gt oracle.
- **Disk:** the data disk floor 4 GB (5.3 GB free on 2026-09-05 evening); an emit tree is ~40 MB; never delete a
  live worktree target or `<emit trees>/cache`; never two Watcom rounds concurrently. **No new worktrees**
  (each costs a multi-GB target dir): new crates build in the same target dir.
- **Nothing goes to the internet**; deliverables are repo files + terminal. **Never systemd; never
  pattern-kill** (stop by PID tree). **The library reads no environment variable** (`tests/no_env.rs`)
  and **the repository names no subject binary** (`tests/no_subject_names.rs`) — both guards stay green
  through every phase; the CLI is a front-end and reads none either (config by flag/file, §3 P2).
- **Original subject source is the implementer-only**; not relevant to this plan's code.

## 1. Context

### 1.1 Why

the owner's productisation goal (2026-09-05): mosura must become **a library exposing a C API usable from any
language, exposing all capability and extensible without ABI churn, exercised by a CLI**, with the corpus
rounds run through that CLI; state lives **flat on disk** (Zig-cache style), no state-owning daemon. The
prerequisites are landed: knobs are values (`switches::Knobs`), diagnostics are caller-configured
(`debug::Config`), tool locations come from `dev-config.toml`, spec/FID data is embedded with a
`--data-dir` override (`resources`), the repository is generic. WP7 is the product proper: the crates,
the spine (operations / options / tables), the session store, the C ABI and its header, the Rust
binding, the CLI, and the recompile rounds through it — architecture §8 phases 0–4; phase 5 stays a pointer.

### 1.2 Intended outcome

1. `libmosura.{so,a}` + `mosura.h` (generated) expose every capability as registered operations over a
   session store; typed entry points for the hot paths.
2. `mosura` (the Rust binding) and `mosura-cli` are written **against the C ABI**; the CLI reaches every
   operation (`mosura call <op>`) and has a hand-designed command tree for the common ones.
3. The corpus round (`emit → compile → verify → verdicts → gates`) is a CLI run over a session, and the
   survey driver, `recompile_check` and the round scripts are retired at verdict-equivalence.
4. The dev tier (oracle captures, censuses, probes, ground truth) is a feature-gated crate in the same
   registry; a release build has no dev tier.
5. Every phase lands with the corpus unchanged where it touches emission (identity gate) and the suite green.

### P1 — `mosura-api`: options, tables and `.tbl`, operations, session store, `Program` freeze/thaw — ~2 weeks

**Findings that shape the design (verified on master 2775eb9):**
1. **Freeze/thaw needs no change to `Program`**: every collection is rebuildable through today's pub surface
   (`Program::new` + pub fields; `Memory::add_block`; `SymbolTable::add`; `FunctionManager::create_function` +
   `set_body`; `Listing::define`; `ReferenceManager::add`; `RelocationTable::add`/`set_relocatable`;
   `SpaceManager::standard()` + `add` + `set_*`). So freeze/thaw are two api-side functions, core untouched. Row
   ORDER is semantic in three collections (`symbols`: `primary_at` falls back to the first; `references`:
   `first_flow_reference_from`; `functions`: the decompile order of `recover_prototypes`) — those tables keep
   insertion order and never set the sorted flag. `ReferenceManager::generation` (a memo) is not restored.
2. **What the decompile path reads from `Program`**: `memory` (initialized blocks as image; read-only and
   uninitialized ranges), `spaces`/`default_space`, `language_id`, `compiler_spec_id`, `function_manager`
   (entries → thunk detection; bodies → `own_effects_over_body`), `reference_manager` (call-typed refs → CALL_RETURN
   overrides), `recovered_protos` (params AND `model`, copied onto the call spec at decompiler.rs:638),
   `recovered_sret`, `sret_callers`, `tail_return_writes`, `proto_scope`, `global_scope_all_loaded`, `knobs`,
   `contract_cache`. `noreturn_functions`/`flow_overrides`/`listing`/`defined_data`/`comments` are analysis-time
   state: frozen for the tables and the snapshot, not read by the bridge. `proto_scope` and
   `global_scope_all_loaded` are set by the survey AFTER analysis → **decompile-time options**, not program state.
3. **`FuncProto.model` is a full `ProtoModel`** (name, print_in_decl, recursive `merged`, two `ParamList`s of
   `ParamEntry`, `effectlist`, two `RangeList`s, extrapop, likelytrash, custom_conventions); for Watcom its lists are
   the body's recovered register lists, so it cannot be re-resolved by name — it is frozen structurally.
   `ProtoModel` derives `Debug` only → round-trip tests compare `format!("{:?}")`.
4. **`SretShape.fields` carries `Datatype`** (recursive: Void, Spacebase(SpaceId), Unknown(n), Char, Int(n),
   Uint(n), Bool, Float(n), Code, Pointer(n, Box), Array(Box, n), Struct(size, fields)) → the interned `types`
   table of design §5.5, used now.
5. **Stage fingerprints cannot be a clean tree split**: the analysis runs the decompiler (switch analyzer, the
   `interface` pass) and `sret_shape` calls `printc::rendered_param_slots`, so a printer edit CAN change
   `program/`. P1 ships four NAMED fingerprints with a conservative definition: `analysis` = `decompile` =
   `src/**` minus `decompile/emit/**` and `recompile/**` (+ the data digest); `emit` = `decompile/emit/**` +
   `printc.rs` + `recompile/{recovery,buildconfig,insn,watsched}.rs`; `recompile` = `recompile/**`. Refinement
   (moving `rendered_param_slots` out of `printc.rs`) is an identity-gated follow-up. Under-invalidation is the
   failure class `measurement-rules.md` exists for; correctness first.
6. **`contract_cache` is order-dependent** (an `InProgress` cycle fallback depends on which function was
   decompiled first): not frozen; a per-function cached result can differ from the same function inside a
   whole-tree run → P3 rounds decompile in entry order as the survey does; documented, not fixed here.
7. **Dependencies**: `memmap2 0.9.5`, `serde_json`, `clap` are in `~/.cargo/registry`; `blake3` and `cbindgen` are
   NOT (→ §7 Q1). Fallback if the fetch is refused: the repo's FNV-1a-128 for the first landing, swapped later
   (keys are pre-1.0 and unreachable sets are garbage anyway).
8. **`Snapshot` v1 is a rendering of a JOIN** (entry names via `primary_at`; refs dedup on `(from,to,kind)`
   dropping `op_index`; `insn` lines are instruction starts; bodies only when non-empty; default space only). P1
   rebuilds a `snapshot::Snapshot` FROM the tables and calls the core `render()` — no second implementation of the
   text format, so parity is structural.

## 4. Order and coordination

```
P0 (promote, identity-gated)  →  P0b (rename core)  →  P1 (api + store; the thaw→decompile identity)
   →  P2 (capi → header → binding → cli; goldens from the examples; C/Python smokes)
   →  P3 (rounds through the CLI; the equivalence gate; retire driver/scripts)
   →  P4 (dev tier; delete spent examples; closure suite + gt-arms + smokes + dist)
```

- P0 first: it is where the risk lives and it is all internal; P0b right after so every later crate uses the final
  names. P1 before P2 because the C ABI is one-liners over api. P3 after P2 because the round is a CLI run. P4 last
  because it deletes what P2/P3 replaced.
- Within a phase: one branch, small commits, suite once at the end; the identity gate wherever core is touched
  (P0 twice, P0b, P1's freeze/thaw commit, P3 commit 1); `gt-arms` at P3 retirement and at P4 closure.
- Estimated ~7 weeks for one implementer (P0 1, P0b ½ day, P1 2, P2 2, P3 1½, P4 1); each phase lands usable.
- Disk: `df -h /data` before every emit and every round; `mosura cache gc` after each landed round once sessions
  exist; the compile cache is reused in place, never copied; scratch emit trees deleted after comparison.
- Cross-phase requirements recorded where they arise: P1 must provide `load.loader=raw|xml` (P2 goldens), `Arc`-backed
  handles (P2 lifetimes), the option keys `compile.cache`/`gates.baseline`/`round.*` as `Environment`/`Result` keys
  (P3), and `session.config.set` (P2's `mosura config set`).

## 8. Do-not list

- Do not change a rendering or a recovered fact while promoting (P0) or wiring (P1–P3): every core touch passes the
  identity gate; an intended tree change is a separate landing through the round.
- Do not flatten `Funcdata` (D4); do not read the environment anywhere (library or CLI); do not name the subject.
- Do not add a `Result`-affecting option outside the registry, or a knob that bypasses the `arms:` stamp.
- Do not keep the old driver/scripts alive past the equivalence gate (E4); do not delete them before it.
- Do not copy `<emit trees>/cache`; do not run two Watcom rounds concurrently (the lock enforces it once P3 lands).
- Do not make the C/Python smokes or live compiles part of the default suite (compiler-free gate).
- Do not set `panic = "abort"` in any profile (the boundary needs unwinding).
- Do not re-run another party's measurements; do run your own change's gate.
