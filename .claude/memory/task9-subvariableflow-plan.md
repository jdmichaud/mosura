# Task #9 plan: port Ghidra SubVariableFlow (subflow.cc)

**Base HEAD `c88ff35` (Task #7 done). Safety net: revert to `c88ff35`.** This is the highest-leverage remaining work — it unblocks 3 held rules at once (SubZext, Piece2Zext, AndDistribute) by making mosura's intermediate graph canonicalize byte-packing the way Ghidra does. Grounded in Ghidra 12.x subflow.cc by the Task #7 agent.

## What it is (subflow.cc, `SubvariableFlow` class, ~lines 26–1546, + 6 driving rules 1547–1746)
NOT a peephole rule — a **worklist-based data-flow transform**. A driving rule spots a *seed* (a wide Varnode from which only a narrow logical sub-value is actually used), builds `SubvariableFlow(fd, root, mask, aggr, sext, big)`, then calls `doTrace()` and, if it succeeds, `doReplacement()`.
- `doTrace` (1410) pushes the seed through data-flow via `processNextWork`→`traceBackward`+`traceForward`, building a shadow subgraph of `ReplaceVarnode`/`ReplaceOp` placeholders (in `varmap`/`worklist`/`oplist`) + `PatchRecord`s (`patchlist`). Returns false (abort, no change) if the logical value can't be fully interpreted, OR if `pullcount==0` (no terminal use).
- `doReplacement` (1435) materializes the transform: creates narrow new ops (via `fd->newOp`) replacing the wide ones, and applies the patches (copy_patch, compare_patch, extension_patch → LEFT/ZEXT/COPY, parameter_patch, push_patch, int2float_patch).
- Net effect on the corpus: the `(zext(hi)<<k | zext(lo))` / `(X&k1)|(X&k2)` byte-packing dissolves into explicit narrow PIECE/CONCAT/zext — exactly the forms whose ABSENCE blocks SubZext (piecestruct 31×-vs-26×), Piece2Zext (floatconv 2×-vs-1×), and hangs AndDistribute (Ghidra fires anddistribute/humptyor 0× on piecestruct because subvar has already dissolved the form). See [[task7-perop-priority-outcome]].

The 6 driving rules (oppool1 slots 111–118, coreaction.cc:5621+; they sit AFTER RuleOrCompare so appending them to `default_rule_pool` = correct priority, minimal reorder):
- RuleSubvarAnd (INT_AND, 1553): seed = `X & c` where consume(out)==c and low bit consumed.
- RuleSubvarSubpiece (SUBPIECE, 1590): seed = truncation; mask = calc_mask(outsize)<<8*sa. THE piecestruct workhorse.
- RuleSubvarCompZero (INT_EQUAL/NOTEQUAL, 1628): single-bit test.
- RuleSubvarShift (INT_RIGHT, 1686): single bit pulled from a byte.
- RuleSubvarZext (INT_ZEXT, 1710): seed = zext output, mask = calc_mask(insize).
- RuleSubvarSext (INT_SEXT, 1729): sign-extension variant (uses `sextrestrictions` trace + aggressive_ext_trim).

## HARD PREREQUISITE (Stage 0, must land FIRST) — bit-level consume
Every driving rule + `setReplacement`(66) + `tryCallPull`/`tryReturnPull` gate on `Varnode::getConsume()` = the bit-mask of which bits are actually USED downstream (backward dual of nzmask). **mosura has ONLY whole-varnode consume** (deadcode.rs, all-or-nothing — its own comment says "Ghidra tracks which bits are consumed … this is the whole-varnode core"). Confirmed: no `consume` field on Varnode (varnode.rs has `nzm` only). Examples that CANNOT be evaluated without it: RuleSubvarAnd `outvn->getConsume() != in(1)->getOffset()`; RuleSubvarSubpiece `(vn->getConsume() & mask) != vn->getConsume()`; setReplacement `(vn->getConsume()&~mask)!=0`.
- Port Ghidra bit-level consume from coreaction.cc `ActionDeadCode` (~3559 `pushConsumed`/`setConsume`, per-opcode backward propagation, 3840 `markConsumedParameters`). Add `Varnode::consume: u64` + a `calc_consume` backward worklist, run as an Action before the rule pool (mirror `ActionNonzeroMask`/`calc_nzmask` at pipeline.rs:205 — same freshness pattern; NOTE the mid-pool-freshness caveat is Task #10's concern, shared family).
- ~300 lines, its own commit, corpus-neutral (consume is only read by the not-yet-wired subvar rules; leave the deadcode bit-refinement OFF so deadcode stays whole-varnode/byte-identical).

## Secondary primitive gaps (small, address as needed)
- `Varnode::is_ptr_flow` — mosura lacks; used only for `aggressive` mode. Default false is fine initially.
- bool-output predicate (setReplacement mask==1 case, `getDef()->isBoolOutput()`) — mosura has no `is_bool_output`; derive from op producing a boolean (BOOL_*/compare opcodes).
- `lone_descend` (Subpiece `big` case) — mosura has the `descend` list; trivial helper.
- `is_persist`/`is_type_lock` (setReplacement sext path) — mosura may lack; only needed for RuleSubvarSext (defer to Stage 4).
- No existing TransformManager/TransformVar framework to reuse — SubvariableFlow uses its OWN ReplaceVarnode/ReplaceOp (only SplitFlow/RuleSplitFlow use TransformVar; NOT needed here).
