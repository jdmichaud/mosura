**THE FIXTURE IS PATHOLOGICAL (decisive context).** partialsplit's scored `func` = the `loadalone` symbol @0x100000 (corpus always decompiles `chunks[0].offset`). loadalone ends with a canary check whose fail-branch does `call __stack_chk_fail` (0x10004d). The datatest script sets `option noreturn __stack_chk_fail`, but the oracle capture (`capture --c`, and mosura's build) do NOT apply it → flow FALLS THROUGH the call into 16 bytes of ZERO PADDING (0x100050-0x10005f, decoded as `add [rax],al` ×7 → the `*pVar2 = *pVar2 + iVar3;` ×7 junk) and then into the ADJACENT function `storeconst` (0x100060+). So the entire tail being compared is unreachable garbage. Both mosura and Ghidra follow it; the −.024 is two decodings of garbage diverging.

**THE ACTUAL MECHANISM (instrumented, decisive).** The two "missing stores" in mosura's C — `*(xunknown4*)((int8)puVar3+8)=0; *(xunknown8*)puVar3=0xffff020000000100;` — are `storeconst`'s body: `0x10006a STORE(RDI+8,#0)` + `0x100071 STORE(RDI,rax=0xffff..)`. RDI here = `r0x38 = COPY r0x20(RSP)` @0x100010 (loadalone did `mov rdi,rsp`), so both stores write THROUGH RDI into the escaped stack buffer `auStack_58` (its address escaped when passed to `func_0x00101000` the memset @0x100023). **mosura DECODES both stores** (confirmed: present in the raw lift AND after `recover_stack` via `dump --prestack`) — it is NOT a disassembler/flow bug. They are eliminated LATER by the pool+deadcode: r0x38=COPY(RSP) is spacebase-typed (infertypes: copy off spacebase ⇒ pointer), RulePtrArith/RuleStoreVarnode + spacebase resolution turn `STORE(RDI+off,v)` into a direct addrtied stack-slot write, then dead-code removes it (the buffer is never read after). **Ghidra keeps them as indirect `*puVar3` stores** — it does NOT resolve the store-through-the-RDI-copy to a named local in this dead branch, so it never dead-eliminates. (Ghidra's C prints `*puVar3`, not `auStack_58[..]=`, confirming it left the store indirect.)
